# COVID-19 detection on chest X-rays

Master's thesis (Big Data & Data Science, Universitat de Barcelona) tackling the Kaggle challenge
[SIIM-FISABIO-RSNA COVID-19 Detection](https://www.kaggle.com/c/siim-covid19-detection):
identify and localize COVID-19 abnormalities on chest radiographs.

The whole pipeline (exploration, data preparation, four models and their evaluation) lives in a single
notebook, [`notebooks/covid_detection.ipynb`](notebooks/covid_detection.ipynb). The notebook is written in Spanish.

## Models

| # | Model | Framework | Data | Experiment folder |
|---|-------|-----------|------|-------------------|
| 1 | CNN with `ImageDataGenerator` (whole image, 4 diagnostic classes) | TensorFlow / Keras | All training images | [`experiments/model_1_keras/`](experiments/model_1_keras/) |
| 2 | Improved CNN with `ImageDataGenerator` | TensorFlow / Keras | Images cleaned via SSIM comparison (`df_cleaned.csv`) | [`experiments/model_2_keras/`](experiments/model_2_keras/) |
| 3 | YOLOv5s object detection (4 classes), imbalanced + balanced variants | PyTorch / YOLOv5 | Reduced + augmented images, NA boxes imputed | [`experiments/model_3_yolov5/`](experiments/model_3_yolov5/) |
| 4 | YOLOv5s object detection (3 classes, no "negative") | PyTorch / YOLOv5 | Reduced + augmented images without NA boxes | [`experiments/model_4_yolov5_no_NA/`](experiments/model_4_yolov5_no_NA/) |

## Data

Images are **not** included in this repository (≈40k files). To reproduce:

1. Download the competition data from [Kaggle](https://www.kaggle.com/c/siim-covid19-detection/data).
2. Place the DICOM folders so that they match the Kaggle layout:
   - `data/train/<study>/<series>/<image>.dcm`
   - `data/test/<study>/<series>/<image>.dcm`
3. The Kaggle CSVs are already in `data/kaggle/`.

All JPG folders under `data/` are generated by the notebook. `data/processed/df.csv` stores paths such as
`./data/train/...`, so keep the DICOM folders exactly where they are.

## Environment

Dependencies are listed in [`requirements.txt`](requirements.txt) and target **Python 3.13**:

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows  (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
```

A CUDA-capable GPU is strongly recommended for training. On Windows the PyPI `torch` wheels are CPU-only.
For GPU training, reinstall `torch` and `torchvision` from the matching index listed on
[pytorch.org](https://pytorch.org/get-started/locally/). For example, for CUDA 13.0
(`cu126` and `cu132` builds are also available for this version):

```bash
pip install --force-reinstall --no-deps torch==2.14.1 torchvision==0.29.1 --index-url https://download.pytorch.org/whl/cu130
```

TensorFlow 2.11+ has no GPU support on native Windows, so models 1-2 run on CPU there (use WSL2 for GPU).

> **Compatibility note.** The notebook was originally developed in 2022 with Python 3.9, TensorFlow 2.5,
> PyTorch 1.10 and NumPy 1.21. It has been adapted to run top to bottom with the pinned dependencies:
> - `imgaug` 0.4 needs `np.sctypes`, removed in NumPy 2; cell 5 restores it before importing `imgaug`
> - the YOLOv5 code at ultralytics commit `cb2ad9f` imports `pkg_resources`, hence `setuptools<81`
> - a few pandas/Pillow calls were updated for pandas 3 and Pillow 10+ without changing results
>
> The YOLOv5 training cells were not re-run with this stack; the committed results come from the 2022 runs.

## Running the notebook

```bash
jupyter lab notebooks/covid_detection.ipynb
```

- All paths in the notebook are relative to the **repository root**. The first code cell changes
  directory to the root automatically when the kernel starts in `notebooks/`.
- Most steps are cached: if an output CSV, JPG folder or `.h5` model already exists, the step loads it instead
  of recomputing it. Delete the file to regenerate it.
- The YOLOv5 sections clone `ultralytics/yolov5` into `experiments/model_3_yolov5/yolov5/` and
  `experiments/model_4_yolov5_no_NA/yolov5/` if they are missing. The import cell loads `utils.plots` from the
  model 3 clone, so on a fresh checkout run the model 3 clone cell (or clone it manually) before the imports.
  The original work used ultralytics commit `cb2ad9f`.
- TensorBoard:
  ```bash
  tensorboard --logdir experiments
  ```

## Outputs

| Output | Location | Tracked |
|--------|----------|---------|
| Train/val splits and evaluation tables | `experiments/<model>/data/` | yes |
| Keras training histories | `experiments/model_{1,2}_keras/model_*_history.{csv,json}` | yes |
| TensorBoard logs | `experiments/<model>/logs/` | yes |
| Keras weights (`.h5`, ~270 MB each) | `experiments/model_{1,2}_keras/` | no |
| YOLOv5 run results (metrics, curves, confusion matrices) | `experiments/model_{3,4}_*/results/<run>/` | yes |
| YOLOv5 dataset `.yaml` files | `experiments/model_{3,4}_*/configs/` | yes |
| YOLOv5 datasets, `runs/` incl. weights (`best.pt`, `last.pt`) | `experiments/model_{3,4}_*/yolov5/` | no |

`results/` and `configs/` are copies taken from the clones' `runs/train/` and dataset `.yaml` files after
training. The notebook still writes to the clones, so copy new runs over manually.
